Formal Verification Tool Uncovers 38 Critical Bugs in GPU Kernels

Columbia and CertiK researchers reveal widespread correctness issues in compiled accelerator code, including flaws in widely-used AI libraries.

By AI Glimpse Newsroom
·
November 22, 2026

A collaborative effort between Columbia University and blockchain security firm CertiK has exposed a troubling gap in GPU kernel reliability. The team deployed TensorLean, a formal verification framework built on the Lean proof assistant, to systematically audit compiled GPU kernels used in machine learning workloads. The results suggest that correctness validation in this critical infrastructure layer remains inadequate.

Researchers analyzed 149 compiled GPU kernel instances and successfully verified only 83 as correct. The remaining 66 kernels contained 38 previously unknown bugs, according to documentation reviewed by AI Weekly. The discovery is particularly significant because two of the most popular libraries in deep learning were affected: FlashAttention, a critical optimization for transformer attention mechanisms, contained 23 of the identified defects, while DeepGEMM, a GEMM (general matrix multiply) library, harbored at least two.

Why This Matters for AI Infrastructure

GPU kernels form the bedrock of modern machine learning systems. These low-level, hand-optimized code sequences execute the mathematical operations that power everything from large language models to computer vision systems. When kernels contain correctness bugs, they can produce silently incorrect results, leading to degraded model performance or subtle numerical errors that cascade through training pipelines.

The scale of the problem revealed by TensorLean suggests the industry has relied on informal testing methods that miss edge cases. Traditional validation approaches rely on unit tests and empirical benchmarking, which cannot guarantee absence of errors across all possible input conditions.

How TensorLean Works

The verification framework represents the first systematic attempt to formally prove properties of compiled GPU kernels at scale. The tool accepts PTX (Parallel Thread Execution) bytecode, the intermediate representation for NVIDIA GPUs, and applies mathematical reasoning to verify correctness guarantees. According to AI Weekly, the researchers created TensorLean to handle the specific challenges of GPU programs, which involve complex memory access patterns and synchronization primitives that traditional verifiers struggle to reason about.

The team, led by Wei Qiang, Ganxiang Yang, Yi Rong, and Ronghui Gu at Columbia, alongside Xupeng Li at CertiK, designed the framework to work with real-world compiled code rather than requiring developers to rewrite libraries in verification-friendly languages.

Implications for Library Maintainers

The findings carry immediate practical consequences for teams maintaining widely-used GPU accelerator libraries. FlashAttention, particularly, is central to inference and training optimizations across the industry. The identification of 23 bugs creates an urgent maintenance responsibility, though the severity of individual defects remains unclear without additional technical details.

This work underscores a broader challenge in AI infrastructure: as models grow larger and more complex, the systems delivering them must offer stronger correctness guarantees. Formal verification, once relegated to safety-critical domains like aviation and nuclear systems, may now be essential for the core libraries powering artificial intelligence.

The research opens a new avenue for addressing reliability in GPU computing, suggesting that similar verification efforts could be expanded across other critical computational libraries that lack formal guarantees today.
